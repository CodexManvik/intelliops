# Correlator benchmark

Stream D owns platform/CI; this doc is owned by the intelligence work
(Stream B) that built the three correlator kinds it measures.

This is the "measure the improvement" half of Stream B: a seeded, reproducible
harness that scores all three `Correlator` implementations
(`river` / `robust` / `trained`, selected by `CORRELATOR_KIND` — see
[ADR-019](../architectural.md#adr-019--pluggable-detectors-the-finetuning-loop-and-llm-assisted-rca))
against five labeled scenarios, and prints precision / recall / false-positive-rate /
detection-latency per (correlator, scenario) pair. One of these comparisons —
robust's false-positive-rate beating river's on `seasonal_cycle` — is
CI-enforced (`services/correlation/tests/test_benchmark.py`), so it cannot
silently regress. The rest of this table is descriptive, not asserted.

## Methodology

**Scenarios** (`services/correlation/benchmark/scenarios.py`), each a seeded,
deterministic generator of `(events, labels)` — a chronological
`TelemetryEvent` stream plus per-event ground truth:

| Scenario | Shape | Ground truth |
|---|---|---|
| `normal_noise` | Gaussian noise around a flat mean. | All normal. Sanity baseline. |
| `seasonal_cycle` | A daily pattern — value plateaus higher during a few peak hours-of-day, repeated across many days. | All normal. This is the scenario a non-seasonal online z-score baseline genuinely false-positives on: the peak-hour plateau is common enough to be "normal" for that time of day but rare enough over the whole stream to look like a global outlier to a single running mean/variance. |
| `point_anomaly` | A stable stream with sharp, brief spikes injected at known indices. | True exactly at the spikes. |
| `sustained_anomaly` | A level shift — the mean jumps and stays shifted over a contiguous region. | True for the shifted region. |
| `correlation_break` | Two metrics that normally move together (`metric_b` tracks `metric_a`'s noise term); `metric_b` diverges for a region while `metric_a` stays normal. | True on `metric_b`'s events during the divergence; `metric_a` is always normal. |

**Metrics** (`services/correlation/benchmark/runner.py`), computed by feeding
every event through `is_anomaly()` (the same call the live consumer uses) and
comparing to ground truth:

- **Precision** = TP / (TP + FP)
- **Recall** = TP / (TP + FN)
- **FPR (false-positive rate)** = FP / (FP + TN)
- **Detection latency** = mean, over each contiguous ground-truth anomaly
  region, of (index of the first flag inside the region) − (region start). A
  region the detector never flags counts as the full region length (a silent
  miss still penalizes the average) rather than being dropped. `n/a` when a
  scenario has no anomaly regions at all (`normal_noise`, `seasonal_cycle`).

**`trained` gets a warm-up + fit pass.** `TrainedCorrelator.fit()` needs
buffered feature history, and `retrain()` at process boot has an empty buffer
(see the honest limit in ADR-019). So the runner is fair to it: it runs the
correlator over the full event stream once to populate its feature buffer,
calls `fit()`, then scores a **second** pass over the same events — meaning
every scored prediction benefits from the fitted model, not just events after
some in-stream fit point. This mirrors "train on history, then serve," the
realistic deployment shape, not "learn while serving."

**One command re-run:**

```bash
uv run python scripts/benchmark.py
# or: ./scripts/benchmark.sh
```

The scenario sizes here are larger than the CI test's (which uses small,
fast scenarios purely to keep the enforced assertion cheap) — this script
trades a few extra seconds for more statistically meaningful numbers. The
generator is seeded, so re-running it reproduces the identical table below,
byte for byte.

## Honest reading

**The headline win: seasonal false-positive reduction.** On `seasonal_cycle`
(a purely normal, recurring daily pattern — every label is `False`), river's
FPR is **0.014**; robust's is **0.002**, about **7x fewer** false positives.
River keeps one running mean/variance per metric with no notion of
hour-of-day, so the recurring peak-hour plateau — common enough to be
"normal" for that hour, rare enough across the whole stream to look like a
global outlier — crosses its z-threshold. Robust buckets its median/MAD
baseline by hour-of-day, so each hour is compared against its own tight local
distribution instead. **This is the one comparison CI enforces**
(`test_benchmark.py::test_robust_beats_river_false_positive_rate_on_seasonal_cycle`,
run at smaller scenario size for speed) — it cannot silently regress.

**Correlation-break recall improves too.** River's recall on
`correlation_break` is **0.380**; robust and trained both reach **0.640**.
The rigid, non-robust z-score baseline (river's running mean/variance gets
inflated by the divergence itself, desensitizing it) misses well over half
the correlation-break region; the median/MAD-based detectors catch nearly
two-thirds of it.

**The trade-off — state it plainly, this is not "new always wins."** Robust
and trained are **more sensitive** across the board: on `sustained_anomaly`
and `correlation_break` they trade meaningfully higher FPR (~0.05–0.06,
versus river's ~0.001) and lower precision (river ~0.95–0.98 vs.
robust/trained ~0.45–0.49) for their extra recall. A robust/trained deployment
will surface more true anomalies **and** more noise than the river baseline —
a sensitivity/specificity trade, tunable via `correlation_z_threshold`, not a
strict dominance.

**Trained ≈ robust on these univariate scenarios.** On `point_anomaly` and
`sustained_anomaly`, `trained`'s numbers track `robust` closely (recall
identical or within 0.02; FPR within 0.01) rather than showing a large
independent gain. `TrainedCorrelator.detect()` returns `max(online,
model_score)`, and the IsolationForest's anomaly margin saturates on a
near-constant feature vector (see the `_MODEL_SCALE` comment in
`trained_correlator.py`) — a 5x spike and a 500x spike score alike to the
forest, so it adds little over the composed robust score on a single spiking
metric. It earns a small independent edge only on `correlation_break`
(precision 0.467 vs. robust's 0.448; FPR 0.049 vs. 0.053) — the multivariate
structure the forest is actually suited to (9-column feature vector including
`value`, `z_online`, hour-of-day, day-of-week, event kind, label count — see
`FEATURE_NAMES`). **The trained model's real value in this build is not a
dramatic univariate detection win — it's the persisted fit/re-fit
("finetuning") loop** (a fresh `POST /retrain` re-trains the IsolationForest
on recently observed behavior and the artifact survives a restart) **plus
reliability learning feeding RCA** (see ADR-019), not a benchmark-table
blowout.

**Costs / assumptions, by detector:**
- **`river` (default)** — no seasonal awareness (the false-positive source
  above); a single early spike inflates its running mean/variance and can
  desensitize it to a second same-size spike later (the classic z-score
  failure robust was built to fix).
- **`robust`** — needs `correlation_robust_warmup` (default 30) samples in
  a given metric+hour-bucket before it scores anything; a metric/hour
  combination with sparse traffic stays cold longer than a metric-only
  baseline would. Its per-bucket windows are **in-process only** for this
  build (not durably persisted — see ADR-019's honest limits), so a restart
  re-warms from scratch.
- **`trained`** — cold-starts identically to `robust` until a `POST /retrain`
  call fits a model (`min_fit_samples=200` buffered feature rows required);
  the fit is **not automatic** — nothing calls it at boot or on a timer in
  this build. Assumes the 9-column feature schema stays stable: a model
  fitted against a different `FEATURE_NAMES` set is refused on load
  (`load_model` returns `False`, correlator stays cold) rather than scoring
  with a mismatched schema.

**This is a synthetic benchmark.** All five scenarios are generated, seeded,
labeled data — not captured production traffic. They isolate one failure mode
each (seasonality, a point spike, a level shift, a broken correlation) by
construction, which is exactly what makes the CI-enforced comparison
non-tautological (river must actually misfire before robust is asserted to
misfire less — see the test's own sanity assertion). It is not a claim about
real-world alert-noise reduction at large; it is a controlled, reproducible
demonstration that the algorithmic change produces the intended effect on
the failure mode it targets.
